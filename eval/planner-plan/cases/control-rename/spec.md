# Rename the work tree to progress tree

## Goal

Everything people and agents see of the "work tree" is called the "progress tree" from now on. The command `pal cli work` becomes `pal cli progress`, with the same subcommands and flags (show, list, open, enter, park, wait, done, stopped, decide, attach, follow-up). The prompt and session lines say `Progress:` where they used to say `Work:`. The code gets the same name, so modules, functions and tests say progress tree instead of work tree. Stored settings keys and the data folder keep their current names; renaming those is a separate task.

## Acceptance criteria

1. `pal cli progress <subcommand>` behaves exactly like `pal cli work <subcommand>` did before, for every subcommand and flag. `pal cli progress --help` lists them.
2. `pal cli work` is removed: `pal cli work …` fails as an unknown command, and it doesn't appear in `pal cli --help`. No alias is kept.
3. The per-prompt line and the session-start/compaction block read `Progress: …`, not `Work: …`, including the root case (`Progress: <scope> root — this session has no node yet`) and the gate's fallback (`Progress: nothing recorded yet`).
4. Every user- or agent-facing string that names the feature says "progress tree" and `pal cli progress`. That covers the CLI summary and help, the Stop gate's send-back messages, the session reminder's "Record as you go" line, the README command table row, the `assets/templates/AGENTS.md.template` rule (now "Keep the progress tree true"), and the `description` text of the three settings in `assets/schema/pal-settings.schema.json`.
5. Source and test files follow the new name: `src/cli/work.ts` → `src/cli/progress.ts`, `src/hooks/lib/work-tree*.ts` → `src/hooks/lib/progress-tree*.ts`, `test/work-cli.test.ts` and `test/work-tree*.test.ts` likewise. Exported identifiers that carry the name are renamed too (e.g. `loadWorkTreeContext` → `loadProgressTreeContext`, `workTreePromptLine`, `stopWorkTree`, `workCommand`). `src/hooks/lib/work-session.ts` and `src/hooks/handlers/work-session.ts` are renamed only if they exist solely for the tree.
6. After the rename, `git grep -iE 'work[ -]?tree|cli work'` over `src/`, `assets/` (except vendored files), `test/` and `README.md` matches only the excluded items listed under Out of scope, plus git-worktree references that have nothing to do with the feature.
7. Existing tree data still loads. A `~/.pal/memory/work-tree/events.jsonl` written before the change shows the same nodes through `pal cli progress show`.
8. All gates in `.dark-factory.json` pass, and the existing test suite covers the renamed command with no lost tests.

## Out of scope

- The settings keys `dynamicContext.workTree`, `dynamicContext.workTreeGate`, `dynamicContext.workTreeDecisionGate`: their names, the code that reads them, `assets/templates/pal-settings.json`, their entries in `test/shipped-surface.json`, and the `{{IF workTree}}` guard in the AGENTS.md template.
- The data folder `memory/work-tree/` and its file names. No migration.
- `memory/work/` (ISAs) and "work tracking" (`work-tracking.ts`, `WORK_TRACKING.md`, session and project history), which are different features.
- `CHANGELOG.md` (generated by semantic-release).
- Git-worktree references (`.claude/worktrees`, `isolation: "worktree"`, statusline worktree fields).
- Any behaviour change beyond the rename.

## Decisions

- Old command `pal cli work`: removed outright, no alias (the user, 2026-10-19).
- Prompt line label: `Progress:` (the user, 2026-10-19).
- Base: a new branch from the latest `canary`. PR #130 is already merged there.
